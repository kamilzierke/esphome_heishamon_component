# Heating-curve dashboard

The [example card](examples/heating-curve-card.yaml) is a single Home Assistant `vertical-stack` card. It requires [Plotly Graph Card](https://github.com/dbuezas/lovelace-plotly-graph-card), available through HACS; the other cards and controls are built into Home Assistant.

Add a Manual card in a dashboard and paste the YAML. Replace every example `sensor.heatpump_...` and `number.heatpump_...` entity ID with the corresponding entity ID from the installed ESPHome device. No device-specific names, credentials or network addresses are included.

## Required entities

All suffixes below use the example prefix `sensor.heatpump_`, except the control entity, which uses `number.heatpump_`.

| Example entity suffix | Component field | Purpose |
|---|---|---|
| `z1_heat_curve_outside_low_temp` | TOP32 | Cold outdoor endpoint |
| `z1_heat_curve_outside_high_temp` | TOP31 | Warm outdoor endpoint |
| `z1_heat_curve_target_high_temp` | TOP29 | High target-water endpoint |
| `z1_heat_curve_target_low_temp` | TOP30 | Low target-water endpoint |
| `z1_heat_request_temp` | TOP27 | Reported curve offset in this context |
| `outside_temp` | TOP14 | Current outdoor temperature |
| `z1_water_target_temp` | TOP42 | Reported zone water target |
| `heating_mode` | TOP76 | Direct/compensation-curve context |
| `z1_sensor_settings` | TOP111 | Zone sensor context |
| `threeway_valve_state` | TOP20 | Space-heating/DHW valve position |
| `operating_mode_state` | TOP4 | Operating mode |
| `set_z1_heat_request_temperature` | SET5, number domain | Offset control |

These are example Home Assistant entity IDs, not guaranteed IDs generated by a particular naming configuration. Read states come from sensors; the number entity is used only for control. The literal context values `Comp. Curve` and `Water Temperature` are component output values, not translated UI labels.

## Interpretation

- The dashed line joins the two configured outdoor/target-water endpoint pairs.
- The solid line adds the reported offset to both target-water endpoints. It is shown only for the supported compensation-curve/water-temperature context and an offset between -5 and +5 K.
- The diamond is the **reported zone water target**, not a measured flow or room temperature.
- The card uses TOP42 for the zone target. It does not use the main target, which may represent DHW during tank heating.
- The plotted line is a linear representation between configured endpoints. It does not extrapolate outside them or model every controller limit, rounding rule or operating transition.

Data is refreshed every five seconds. Invalid/missing inputs do not become zero-valued points. Curve-offset controls are hidden outside the compensation-curve/water-temperature context. The native control uses the number entity's configured bounds and step; the intended offset range is -5 to +5 with a step of 1.

**The plus/minus controls send real setpoint commands.** The plotted shift remains based on reported sensor state, rather than a local preview or optimistic target.

The current context-dependent number entity still exposes Celsius metadata. Consequently, native controls display a Celsius symbol even when the setting represents an offset in K. The readback summary and shifted-curve legend label that offset explicitly in K. Changing the displayed label does not correct the underlying entity metadata; that remains a separate limitation.

## YAML compatibility

Keep coordinate keys written as `"y":`, including the legend position. Home Assistant's editor uses a YAML 1.1 schema, where an unquoted `y` can be interpreted as a boolean key. Losing the trace's Y array causes Plotly to draw point indexes such as 0 and 1 instead of water temperatures. This example quotes the keys and uses `raw_plotly_config: true` with linear axes for an XY plot rather than a history plot.

The configuration follows the card's [raw Plotly configuration and universal functions](https://github.com/dbuezas/lovelace-plotly-graph-card/blob/master/readme.md). YAML schema agreement and local Plotly rendering have been checked; final layout also depends on the installed card version and dashboard width.
